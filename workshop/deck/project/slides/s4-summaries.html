Step 4 · Likely question

Aren't summaries usually fine?

Often they are: automatic summaries of 3,300 to 6,100 characters kept every task's status in rehearsal. They are not fine when:

Something was only said in conversation. Lasting rules belong in CLAUDE.md.

The exact detail matters. Summaries warn that exact code and errors may be missing.

The run is long. Each compaction summarizes the previous summary.

The record did not come back from disk. At most five files, each under 5,000 tokens.

Work was half done. A summary records belief, not what is on disk.

Compaction itself fails. "Autocompact is thrashing" ends the turn.

Someone steers the summary. /compact instructions, or a "Compact instructions" section.

The hook costs one file read and runs after every compaction.

Stop Guard Cook-Along · Step 4 · Full answer with sources: guide, step 4

The docs say instructions given only in conversation may be lost. Claude Code's own summary text says: "If you need specific details from before compaction (like exact code snippets, error messages, or content you generated), read the full transcript". Context a hook added earlier is summarized too, which is why restore-tasks.js runs again after every compaction. In rehearsal, the thrashing error also cleared an active /goal.
