# Bugs (history)

Fixed bugs, archived from `BUGS.md` so the active list stays scannable. **Archaeological**: read only when consulted. When a bug is fixed, append its entry here rather than to the active file.

The bug breakout file at `bugs/<slug>.md` (when present) stays in place as the historical diagnosis record; the entry here is a brief description of the fix and the commit it landed in.

## Cross-reference resolution

`/nightshift:ready` does **not** parse this file for work; it reads it only for the line-discipline check and the link checks, which verify links into it and count its links as keeping the records they name reachable. When a bug is fixed, every other `**Requires:**` line in `FEATURES.md` / `BUGS.md` that referenced it is edited at the same time to drop the now-satisfied reference (mirror of the `FEATURES.md` convention). The active `Requires:` lines therefore describe what is *currently* blocking; this file is purely archaeological.

### Output-loop attempts record no token usage

### Resumed Claude dispatches record cumulative session usage

Fixed on 2026-10-03 in the 3.3.3 candidate, run `e92922e8-d20f-4674-907c-bf3277f5f184`, commit "fix(runtime): record only a resumed Claude attempt's own usage". `runClaude` in `internal/runtime/hosts.js` keeps the session's cumulative `result.modelUsage` total as `threadTokens` on fresh and resumed attempts, so receipts pass it on as `priorThreadTokens` the way Codex receipts do, and records a resumed attempt's own usage as that total less the previous one. The usage is null when the host did not continue the session, the earlier total is unknown, the host omits `result.usage`, or the difference falls below the invocation's own `result.usage` total. `resolveContinuation` in `internal/runtime/continuation.js` now discards a receipt's total only when a later dispatch on the session launched a host, recording a pid, so a resume refused before launch keeps the baseline; after a later attempt that did launch, a Claude resume records unknown usage, since Claude cannot recover the baseline from the host as Codex does. A live check on Claude Code 2.1.288 with `claude-haiku-4-5` confirmed the cumulative reporting: a fresh call used 3,151 tokens, its resume reported a `modelUsage` total of 6,458 and a `result.usage` total of 3,307, and the runner recorded 3,307. [The runtime reference](../internal/runtime/REFERENCE.md#independent-assessment) describes the result.

Found on 2026-10-02 by a documentation review of backlog entries, from the records of run `61461833-3c7e-4449-8282-67b3df7dd564` on installed 3.3.1, and tracked by the user the same day. When the runtime resumes a Claude session, whether for a lead's reassessment or dialogue turn or for a skeptic's dialogue turn, the attempt records the session's cumulative usage instead of the resume's own: `runClaude` in `internal/runtime/hosts.js` sums `result.modelUsage`, which Claude Code reports cumulatively across a resumed session, while `result.usage` carries the invocation's own figures. In that run the resumed docs review `250cbdf8` recorded 2,634,318 tokens, exactly the fresh review `9e79e429` (1,671,065) plus the resume's own 963,253 in every component, and its event log's `total_cost_usd` of $9.52 is likewise cumulative against about $4.53 for the resume alone. [The runtime reference](../internal/runtime/REFERENCE.md#independent-assessment) and [the resumable reviewer spec](specs/resumable-reviewer-dialogue.md) say "Claude usage stays per invocation"; completed Codex resumes are unaffected, since the runtime records the turn's increment, while one that ends as an output loop records no usage at all, as [Output-loop attempts record no token usage](#output-loop-attempts-record-no-token-usage) describes. Every resumed Claude dispatch therefore overstates its usage by the whole earlier session, so run totals and any budget ledger built from receipts are inflated: the run's local morning report gave about 8.3 million recorded tokens where counting the resume's own usage instead gives about 6.6 million, and the quick-win entry published in commit `334ac4c` cited the cumulative 2,634,318 as the resumed docs review's cost. Record a resumed Claude attempt's own usage as the difference from the session's previous cumulative `result.modelUsage`, rather than switching to `result.usage`, which omits auxiliary evaluators that `result.modelUsage` includes, as [the v3 acceptance report](reports/v3-acceptance-20260908.md) records. Claude receipts keep no separate cumulative field today (`threadTokens` is null), so store one as Codex receipts do and pass it through the continuation path Codex uses (`priorThreadTokens` in `internal/runtime/continuation.js`). That path leaves the baseline unknown whenever a later worker recorded the session after the named receipt, failed ones included, which covers not only a resume that failed on input drift or a timeout and was resumed again but also a resume refused after registration and before launch, since a resumed dispatch registers its session first; Codex recovers its baseline from the host's replay, while Claude cannot, so either take the baseline from the last attempt that actually ran or expect unknown figures in all those cases. Record the usage as unknown rather than cumulative when the host did not continue the session, which `runClaude` already detects as `continuedSession`, when the baseline is unknown, when the difference would be negative, or when it falls below the invocation's own `result.usage` total, which would mean the host had stopped reporting cumulatively; this extends the unknown result that `resumedUsage` in `internal/runtime/hosts.js` gives Codex for an unknown baseline or a negative difference. Update the runtime reference's "Claude usage stays per invocation" to describe the result. Add tests with resumed sessions' events, including a chained resume, a skeptic dialogue turn and an unknown baseline. Runtime changes ship with a version increase.
