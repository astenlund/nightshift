# Bugs (history)

Fixed bugs, archived from `BUGS.md` so the active list stays scannable. **Archaeological**: read only when consulted. When a bug is fixed, append its entry here rather than to the active file.

The bug breakout file at `bugs/<slug>.md` (when present) stays in place as the historical diagnosis record; the entry here is a brief description of the fix and the commit it landed in.

## Cross-reference resolution

`/nightshift:ready` does **not** parse this file for work; only the line-discipline check reads it. When a bug is fixed, every other `**Requires:**` line in `FEATURES.md` / `BUGS.md` that referenced it is edited at the same time to drop the now-satisfied reference (mirror of the `FEATURES.md` convention). The active `Requires:` lines therefore describe what is *currently* blocking; this file is purely archaeological.

## Entries

- **Unattended Stop hook blocks yielding to a present user for a blocking decision.** `internal/runtime/hook.js` now permits the unattended yield when nothing is actionable, no worker is active and every remaining blocker is a `user-decision`, with a message that the run is paused on those decisions and that session closing remains due; `capability`, `resource` and `dependency` blockers keep resisting until closing is recorded, and a permitted yield leaves the revision and reminder count untouched. Hook fixtures cover the permitted state and each resisting state, and `internal/runtime/REFERENCE.md` and `internal/workflow.md` describe the pause before closing. Shipped in plugin 3.0.9.
- **Unattended Stop hook blocks yielding while a background dispatch runs.** The read-only runtime `wait` operation (`internal/runtime/wait.js`, exposed by `internal/runtime/cli.js`) observes a saved worker until it finishes, its runner process disappears, the run stops, the run deadline passes or a bounded timeout elapses, and returns the project-relative receipt path with an explicit reason; the reference, brief and handover skill direct the controller to await a background dispatch inside the turn with it, so the Stop hook keeps resisting a yield while a dispatch worker is active. Runtime fixtures cover timeout, mid-wait completion, a missing runner racing a committed completion, an `unverified` worker, a stopped run and the deadline. Shipped in plugin 3.0.9.
- **Init-backlog flags non-document files that mention unmigrated `.claude` paths.** `Setup.referenceDecisions` in `internal/setup.js` now flags a file outside the Markdown, JSON, TOML and YAML set only on a mismatch: an undeclared file whose rewrite would change its bytes, or a declared active consumer whose rewrite is a no-op, which is the signal for a computed or unsupported path literal. An undeclared script that only mentions unmigrated `.claude/` paths needs no decision; the init-backlog skill text describes the rule and a setup fixture covers all three cases. Shipped in plugin 3.0.7.
- **Init-backlog translates every `.claude/` ignore rule into a `.nightshift/` twin.** `Setup.preservePolicies` in `internal/setup.js` now asks `git check-ignore --no-index --verbose` which root `.gitignore` lines actually match the migrated file sources and migrated legacy directories, translates only those into the "Nightshift migrated ignore rules" block, and precedes the block with a blank line when the existing content does not end with one; host-only rules such as `.claude/skills/` stay untranslated. A setup fixture mixes migrated and host-only rules and checks that a rerun stays idempotent. Shipped in plugin 3.0.7.
- **Published version surfaces can drift on release.** `tools/release-gate.js` compares the outgoing range with the published baseline and fails when bundled non-test paths under `skills`, `internal` or `hooks` or non-version manifest fields change without a version increase, when the manifests differ, when the version decreases, or when the README status line does not carry the manifest version. It runs as the repository pre-push hook (`git config core.hooksPath .githooks`) and in CI against the push or pull-request baseline, the packaging test asserts the README status matches the manifests, and the Codex handshake has read its version from the manifest since 3.0.2. Shipped in plugin 3.0.3.
- **Mixed backlog line endings abort init-backlog instead of being repaired.** Controlled backlog files with mixed LF and CRLF endings now produce an approved mechanical repair that uses the existing newline policy, asks for LF or CRLF when the policy is genuinely ambiguous, composes hard-wrap repair when needed, and retains byte-exact backup, recovery, and resume guarantees. Invalid UTF-8, bare carriage returns, and mixed endings outside the backlog surface remain blocking. Shipped in this commit (plugin 2.6.20).
- **Init-backlog rejects Windows forward-slash project roots as noncanonical.** Root validation now treats forward slashes as Windows separators only when their native-spelling replacement matches the exact canonical path, reservation returns that native `canonicalRoot`, and the skill carries it through the request record and remaining spool lifecycle. Other aliases remain rejected. Shipped in this commit (plugin 2.6.17).
- **Shared sync-gists skill names the wrong backlog command.** Corrected the canonical personal `sync-gists` skill's Nightshift suite note from `init-workflow` to `init-backlog`, so the documented command matches the repository and shipped plugin. Shipped in this commit.
- **Feature breakout dependency lines drift from the active index.** The index is now the sole dependency authority: `**Requires:**` holds in-backlog links only and a new optional `**External:**` line holds external primitives, every breakout file under `features/` and `bugs/` lost its dependency line, and `skills/ready/ready.js` reports bare text in Requires, links or none. in External, an empty label, and any dependency line found in a linked breakout file as structural errors carrying a remedy. Every prose surface (index headers, ready/exploring/handover/revise-docs/init-backlog skills, README, AGENTS.md) describes the two-line convention. Shipped 2026-08-22 in the range 17d24cd..HEAD (plugin 2.6.0); diagnosis stays in [`bugs/feature-breakout-dependency-drift.md`](bugs/feature-breakout-dependency-drift.md).
- **Plan refreshed stamps are rejected by the provenance grammar.** `REFRESHED_PROVENANCE` in `skills/spec-agreement/spec-agreement.js` accepted only `revise-spec refreshed` lines while the graduated grammar already accepted both loops, so a plan edited after its graduated stamp could not carry the `revise-plan refreshed` stamp that handover's post-stamp-edits rule prescribes. The regex now accepts `revise-(?:spec|plan) refreshed`, and a spec-agreement test writes a plan refreshed stamp through `writeProvenanceStamp` and reads it back, including the applied-retry path. Shipped 2026-08-22 (plugin 2.6.1).
