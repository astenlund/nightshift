# Creation hydrates every completion snapshot to judge a completed run's discharge

Moved from BUGS.md on 2026-11-11, when the user chose at the first pruning pass to fold it into [Cut store v4 and reduce the release system](../features/store-v4-cut.md), whose work removes the lines it concerns. The text below is the entry as it stood.

Split from the fix of [A completed run with a current accounting marker blocks every handover](../BUGS_HISTORY.md#a-completed-run-with-a-current-accounting-marker-blocks-every-handover) on 2026-11-03, as the structural half the user chose at inbox triage that day to track ("Fix A now, track C"). The creation gate in `internal/runtime/creation-consistency.js` still hydrates, through `accounting.resolve`, every task check and review snapshot, docs-exemption snapshot and closing evidence of each completed record's latest state before `historicalDischarge` judges its discharge, superseded snapshots included, although [the handover-only delivery record](../features/handover-only-delivery.md) says the gate is not to hydrate arbitrary assurance bodies. Since 3.3.27 that evidence is charged to an 8 MiB allowance of each record's own, so completed runs no longer accumulate against one another, but a single long run whose own completion evidence passes 8 MiB still refuses every new handover, and the gate reads every completed record's evidence on every handover.

Verify completion evidence without hydrating it, checking artifact identity and resolving on demand only the snapshots `historicalDischarge` consults, so the charge stops growing with superseded evidence; the `snapshotValid` contract and `closingDischargedSince` change with it. Runtime changes ship with a version increase. Tracking does not authorize implementation.
