# Bugs

V2 entries are preserved in [the historical index](migration/v2/BUGS.md) and [MIGRATION_STATUS.md](MIGRATION_STATUS.md). Their retained needs are consolidated into the agreed v3 work or its continuations; this is not a statement that old bugs were fixed or proposals shipped.

**Before adding an entry, look for a feature to fold it into.** If an active feature in `FEATURES.md` would remove or rewrite the lines the fix touches, so that the fix would not survive the feature in its current form, add the fix as one line under that feature record's `## Carried fixes` heading, beginning with the name of the slice whose work removes those lines when the feature is sliced, giving the observed failure, its location, what the replacement must do and a link to the evidence, and create no entry here. When the feature would remove only part of what the fix changes, and that part fails and can be verified on its own, carry that part the same way and add an entry here for the rest that names the part carried and links the feature's `## Carried fixes` heading, while the carried line links its evidence rather than that entry, so either can ship first; a fix whose parts cannot be separated stays whole. A feature that merely touches the same module does not qualify, and neither does an Exploring draft, which has not settled what it replaces. A repeat adds a date to that line, never a paragraph. A tenuous match, or a feature invented so there is somewhere to fold into, means an entry here as before. A defect that blocks runs now gets the smallest stopgap, noted on its carried line, without an entry of its own. `FEATURES.md` describes how carried fixes ship and what happens to them when a feature is retired.

### Unwrap inserts a space after a line-end hyphen or slash

Reported from Ring-O-Meter-Private on installed 3.3.31 and tracked by the user's inbox triage decision on 2026-11-08, from the maintainer inbox report `2026-11-08-unwrap-space-after-line-end-break.md`. Running `init-backlog` setup `apply` with `options.unwrap` joined every hard-wrapped line with a space, including lines where the wrap had split a compound word or a path: `chord-` and `aware` became `chord- aware`, and `.claude/skills/` and `sketch-on-tablet/` became `.claude/skills/ sketch-on-tablet/`, which breaks the path. The report counts 165 damaged hyphen joins and 9 slash joins across the 79 migrated files, found by a documentation review and repaired in that project against the pre-migration files. Ready reports nothing, since links are unaffected, and a search for the compound or path then misses those occurrences. `joinContinuations` in `internal/backlog-catalog.js` always inserts one space, whatever the line ended with.

The correct rule is open. A line-end hyphen is ambiguous, because a suspended hyphen such as `single-` before `and multi-` does need the space, and that backlog holds five of them; a line-end slash has not been analyzed separately. `comparisonText` in `internal/template-text/document.js` copies the join, so a fix that alters a block's comparison text needs `COMPARISON_RULES` increased and the retired list regenerated. Shared catalog code, so keep Ready and setup coherent, cover the rule with unwrap fixtures and ship with a version increase. Tracking does not authorize implementation.

### Shared block model misreads a fence opened on a list item's marker line

It reads the fenced lines as list continuation and the closing fence as an opener, so every later line reads as fenced code. `unwrapText` on such a record joins the code onto the marker line and breaks the fence, which `--write` would persist. The user chose to track it at triage.

Give the shared block model list-item context for a fence opened on a marker line, with unwrap and Ready fixtures, then remove the documented link-notice limitation. Behavior changes for both consumers ship with a version increase. Setup's [template adjudication](specs/setup-index-text-adjudication.md) hashes text through the same block model, so if the fix alters a block's comparison text, increase `COMPARISON_RULES` and regenerate the retired list. Tracking does not authorize implementation.
