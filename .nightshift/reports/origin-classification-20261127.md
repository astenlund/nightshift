Nov 27, 2026

The by-hand classification behind number 8 of the fortnightly check in [the assessment worklist](assessment-worklist-20261018.md), for the check of 2026-11-29: every entry added to [BUGS.md](../BUGS.md) or [QUICK_WINS.md](../QUICK_WINS.md) from 2026-11-16 to 2026-11-29, classified by where it came from. The window was read on 2026-11-27, two days before it closes, so an entry added on 2026-11-27 to 2026-11-29 after commit `f36a26380acdaa5b98155d0dd309ec8c4ef2a6d9` is not counted here. It continues [the origin classification of 2026-11-15](origin-classification-20261115.md) and applies that report's rules unchanged: the bugs table counts a review fix only where a repair answering a review finding introduced the defect, and an instruction change only where a later edit of instruction prose did, so a defect in prose as first written is original implementation there; the quick-win table counts a review fix wherever a review raised the entry and deferred it, or it arose from a repair made in response to a review finding, taking precedence over the other classes, and an instruction change wherever the gap lies in prose agents follow (the operating brief, a SKILL.md, AGENTS.md, a runtime or releases reference, init-backlog templates, reviewer prompt text) with the remedy there. Unclear covers an entry whose provenance does not place it, a host verification, a naming preference, a feature request whose remedy is split between code and instructions, or run and repository bookkeeping. The two tables' counts are not combinable. The maintainer accepted the classification as drafted on 2026-11-27.

## Method

The entries come from Git history, not from the indexes as they stand. A scratch script, run at `HEAD` `f36a26380acdaa5b98155d0dd309ec8c4ef2a6d9`, listed every commit touching either index with `git log --reverse --format=%H|%aI|%s`, kept the 62 whose author date falls from 2026-11-16 to 2026-11-29 (the first `73fa8151fe4da5d93886df76521245b2d5466841`, 2026-11-16), read the `### ` headings of BUGS.md, QUICK_WINS.md, BUGS_HISTORY.md, QUICK_WINS_HISTORY.md, FEATURES.md and FEATURES_HISTORY.md at its parent `db25a4de9447139bf8387ee48882c11a21e93c28` (315 titles), and took each `### ` heading a window commit adds to either index (from `git show --unified=0`) whose title, a linked heading `### [Title](record)` compared by its title, was not among them. That gave 31 headings. The same script listed every window commit touching the six files that both removes and adds a heading, after dropping titles that a commit both removes and adds (moves to a history file), and found five. Two rename entries added in the window and are counted once under their current names: `8ca6a6defbdcddd6c52f3386a681eb583dec58f9` renamed "Decide whether hold and stop are admitted on a complete record" to "Decide whether hold, stop and block are admitted on a complete record", and `cda7a423df1cc7dda91c33e1d4e7418d220e74c8` renamed "Refuse a skeptic dispatch whose assigned ids name no finding of its target" to "Refuse a skeptic dispatch that names an id outside its target's findings". Two rename an entry that existed before the window and are left out: `ea1cf659d430a11684902795a3c08e9a0badb0b3` renamed "Name a stale docs review as a fresh target after a docs repair elsewhere or say why not", added on 2026-11-15 and classified in the report of 2026-11-15, to "Name a stale docs or spec assessment as a fresh target after an edit elsewhere or say why not", and `0145c387c0c03ed9a7825ec85a724b7f47d41f7d` restored the original title. The fifth, `a4cc89b40a9433e7c5dbd061f1ff93b92629ca54`, merged the window quick win "Move backlog conventions out of the index files into a shipped reference" and the Exploring draft "Shared BACKLOG.md meta-index" into the draft "Give shared backlog conventions one home"; the quick win stays counted, with that draft as its current location, and the draft heading is a feature, not counted. That leaves 28 entries, 13 bugs and 15 quick wins. Archived, folded or moved entries are included with their current location: four bugs now in BUGS_HISTORY.md, one bug folded by `438e4b254916bedb63414ce844cbea98b99becc4` into the quick win "Retry a review attempt that ended in an output loop", one quick win in QUICK_WINS_HISTORY.md and the merged one above. Each entry was classified from its whole text where it now lives, printed by a scratch script, or from the commit that added it when it is no longer an index heading (`d62bd964b3caf94e794df910a2a6f8e5001d2d25` and `711850db2a6c30b19caec2a06ef012f881979778`). The per-class counts below were taken with a command over the tables of this file.

## Contestable classifications

- "A skeptic over several findings exhausts structured-output retries" is unclear because its entry says the cause is not established and names neither host nor model; if the failure is the Claude terminal reason the quick win it was folded into records, it is a host output failure rather than a defect in Nightshift code, and if the remedy is bounding a skeptic's assignment it would be original implementation.
- "A controller closes a run on a Stop hook continuation while the user is asked to triage" was fixed by guidance only, but the entry leaves open whether the brief's absent-user path or the hook's continuation text led the controller to close, and names no later edit of the brief as the cause, so under the narrow rule it is original implementation; it would be an instruction change only if the absent-user path were shown to have been introduced by a later edit.
- "Decide whether archived bug records carry a closing note" and "Stop hook keeps reminding while follow-up triage waits on the user" are new headings in the window, but their text was split out of entries that existed before it: the first from the paragraph recorded on 2026-11-03 in "Tell the init-backlog templates where retired features go" (`6bfbd80e4a7621f3198db876603c5bfc35394d37`), the second from a carried fix of the feature "Keep a handed-over run open for triage after delivery". They are counted, as the report of 2026-11-15 counted a split; read as pre-window entries, the window would read 12 bugs and 14 quick wins, with number 8 unchanged.
- "Give Ready's report its counts from the parser" and "Move backlog conventions out of the index files into a shipped reference" are unclear as remedies split between code and instructions. The first could be read as original implementation (the parser output lacks a count); the second as an instruction change, since most of its remedy is relocating template prose into a shipped reference, with setup code writing only the pointer. Neither reading changes number 8.
- "Decide whether hold, stop and block are admitted on a complete record" was found while drafting a spec, not by a review, so it is original implementation; its widening to cover `block` came from a question raised in that spec's review. Counted as a review fix, it would raise the quick-win review fixes to 6.
- "Verify the verdict tripwire's call-graph exclusions" is counted as a review fix because a docs skeptic raised it and the triage deferred it; read as a skeptic's observation rather than a review finding, it would be original implementation and number 8 would read 4 quick wins.
