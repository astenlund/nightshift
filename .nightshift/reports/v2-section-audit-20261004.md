# Section-level audit of capabilities in v2 records

Preserved as a durable report on 2026-10-04. On 2026-10-03 the user found that controller-run experiments, the controller designing and running bounded experiments, had silently left the backlog: it lived as one section of an unshipped v2 draft, the night manager and shift supervisor umbrella, whose Simplify disposition did not name it. It is tracked again as [Controller-run experiments](../features/controller-run-experiments.md). The [2026-09-20 reconciliation](v3-capability-reconciliation-20260920.md), the [2026-09-21 shipped-capability audit](pre-v3-shipped-capability-audit-20260921.md) and the [2026-10-01 audit](v2-capability-audit-20261001.md) checked work units and shipped behavior, not the sections inside them, so the user asked for a second search that checks every capability a v2 source names, section by section. The user decided every case at triage the same day. The raw evidence (the brief, the seven group reports, the four refutation reports and the triage ledger) remains in [the audit evidence directory](../../.tmp/lost-features-20261004/).

## Method

Seven fresh-context agents read the sources read-only at checkout `d3b2651`, each owning one batch: the unshipped v2 drafts and records that have a [MIGRATION_STATUS.md](../MIGRATION_STATUS.md) row, in four batches; the v2 quick-win, bug and pattern indexes and the v2 feature index conventions; and, in two batches, the records of work that shipped before or at v3, for the parts they deferred and for shipped parts that neither earlier audit mentions. Each agent enumerated every capability its sources name and gave each one verdict: shipped in v3, tracked by an active entry that names it, retired by an explicit disposition, simplified by a disposition that names it and replaces it with less machinery, or unresolved. A Simplify, Replace or merge disposition that does not name the capability counted as unresolved even when its destination covers the area, and a retirement whose rationale does not address a distinct capability was marked as such. Before an unresolved verdict, each agent searched the capability's key terms with synonyms over the backlog, reports, migration records and shipped instructions, and read the sections where it would live.

Four further fresh-context agents then tried to refute each unresolved case and each simplification the auditors flagged as worth re-checking, against the repository rather than by plausibility. Merging two duplicate pairs made the 22 cases 20 items. None was fully refuted and four were partly refuted, so triage decided their surviving part. Several accounts were corrected, as listed below.

Triage took those 20 items, one simplification close enough to them to sit beside them (item 6) and one finding outside the audit's scope (item 22). The user then chose to triage the 21 remaining flagged simplifications as well, making 43 items.

## Corrections found by verification

- Item 3: setup started through the installed launcher is already serialized per project, because the launcher refuses a second operation on a project that is not read-only (`resource-operation-busy` in `internal/releases/service.js`). The audit and the refutation pass missed this, and the review of these records found it, so the gap is setup reached outside the launcher. Whether a direct second setup fails with a raw error, as the auditor assumed, or resumes the first one's migration is unverified; no probe ran.
- Item 5: repairs that answer a review finding already carry a recorded classification against the accepted commitments; only edits that no finding drove leave no judgment. `spec-accepted` stores content hashes, not the accepted text.
- Item 7: the gate at line 102 of the source covered only the MVP slice, which shipped in 2.5.0; the ongoing block is the packaging slice's, whose disposition was Keep.
- Item 8: update instructions are missing for Claude Code users as well as Codex users; invocation is documented.
- Item 13 and 14: these authoring habits also fed the Authoring guidance overlay, replaced without naming them, so they are closer to unresolved than to retirements that leave them unaddressed.
- Item 15: the rule that "reviewer requested it" is no basis ships in the disposition basis; only the record inside the spec is missing.
- Item 16: shipped text already re-assesses every revised spec draft; only an explicit rule for a readback revised at the user's request is missing.
- Item 17: what reviewers receive comes from one module; the lens text is written twice, in the operating brief and in `internal/runtime/review.js`.
- Item 21: the v2 engine never carried the "expect subtler residue" calibration the light-mode draft claimed for it.
- Item 34: the auditor counted V3-MIGRATION.md's context list as v3's, but no run loads it; the brief says only "Investigate the actual problem before editing".
- Item 43: a review copy whose shutdown is unconfirmed is left with no marker; `cleanup.json` appears only when a removal already judged safe fails. In this repository on 2026-10-04, `.nightshift/runs/c/` held 163 copy directories, 152 MB, the oldest from 2026-09-28.
