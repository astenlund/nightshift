# Seeded-defect rerun after the 3.3.18 prompt change

This report records the [seeded-defect suite](../specs/seeded-defect-suite.md) rerun that validates the prompt change in 3.3.18, compared with [the corrected seeded-defect baseline](seeded-defect-baseline-20261025.md) the targets were set from. The change defines critical, important and minor in lead assessment prompts with the suite's severity rubric, states the layout of a probe's copy in every prompt, and attaches recorded checks to every assessment. The suite's fixtures carry no recorded checks, so the rerun's prompts took the change's empty branch: every prompt, lead and skeptic, carried the probe layout sentence, the line saying that no recorded check ran on unchanged inputs and that execution evidence comes from probe requests, and the tests-and-evidence brief rewritten to judge from the attached checks and their reproductions, and every lead also carried the severity definition. Attaching checks that exist is covered by deterministic tests alone. The varied input, the review machinery, also holds the Vibe reviewer commits made since the baseline, one of which, `348a810e`, changed one sentence of every Claude prompt: where no probe has returned evidence, the execution paragraph now says so ("No probe evidence has been returned for this assessment yet.") instead of pointing at `context/probes/`.

## Method

Environment: Windows 11, Node 22, Claude Code 2.1.312, Opus 5.5 as lead and skeptic, on the same 23 fixtures, fixture set hash `71d708fb5ea5`, conventions hash `fefb60b9ff27`. Each fixture ran twice under a budget the user set at 3,000,000 tokens, then two `--retry` passes over `branch-switch-shell`'s second repetition. Its first lead requested a probe, which the suite does not run, and reported itself incomplete while it waited; the first retry ended in a host failure (`structured_output_retry_exhausted`); the second completed. No other lead in this run or the baseline requested a probe. Every dispatch shares one identity: review machinery `fe9c0a9c5bf5`, dispatching harness `93320e133e26`, commit `cbd195ea`, so the run is not mixed. That commit was later amended before publication, so it is not in the published history: the review that preceded the push changed how a check and its reproduction are paired and described when recorded checks exist, a path no fixture reaches, and reworded the empty-set line to say that no passing recorded check ran on unchanged inputs, so 3.3.18 ships a different machinery hash, and its prompts differ from those the fixtures received in that one word. The run spent 2,712,804 tokens, the superseded attempts included. Raw artifacts stay in `.tmp/4722571d-suite/prompt-change`.

The grader changed since the baseline was graded, so a copy of the baseline run, in `.tmp/4722571d-suite/baseline-5-regraded`, was regraded with the current grader, hash `4e5adb8f4c35`; its figures are unchanged.

## Adjudication

All eleven unmatched findings were adjudicated false, nine counting as unmatched confirmations and two, on the clean port-validation fixture, as clean-change false positives. Nine follow the baseline's rulings: check-environment's timeout stopping only the command it started (twice), message quoting in port-validation (twice), the duplicated host list in registry-reconcile (twice), re-exporting from `src/index.js` (twice), and validating a change's shape. The other two, one per repetition of revision-history, are new: `Store` exposes no way to read the head revision or the current state except through the value `apply` returns. They were adjudicated false because the requirement asks only to apply changes and reconstruct earlier revisions, and `apply` returns each new revision number.

## Qualifications

The comparison is confounded by the dispatching harness: its hash, over `tools/seeded-defects.js` and the Vibe launcher, differs from the baseline's because the Vibe reviewer commit `348a810e` changed both, and the spec compares a later change against a baseline dispatched by the current harness. The user chose on 2026-10-29 to record the result with this qualification instead of running a new baseline. The severity gain is far outside the baseline's spread and follows the rubric the change adds to lead assessment prompts, though the rerun cannot separate it from the probe-evidence sentence that commit changed, from the change's own empty-checks line and tests-and-evidence brief, which every lead also carried, or from the host update named later in this sentence; the smaller movements in unmatched confirmations and tokens cannot be separated from that sentence, the harness change, the change's own empty-checks line and tests-and-evidence brief, or the host update from Claude Code 2.1.310 to 2.1.312, which the spec treats as informational, nor can the one probe request, which no lead made at baseline and which followed a prompt that, for the first time, said execution evidence comes from probe requests. Each figure rests on two complete repetitions of one model on one host version, and adjudication is the maintainer's judgment on the controller's proposals, made against the fixtures' requirements and the earlier rulings.
