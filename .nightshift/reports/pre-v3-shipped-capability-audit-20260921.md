# Pre-v3 shipped capability audit

Preserved as a durable report on 2026-09-21. The audit and its observations were completed on 2026-09-20. Original scripts, snapshots, logs and probe JSON remain in [the audit evidence directory](../../.tmp/feature-history-audit-20260920/); unqualified evidence filenames below resolve there. The [triage record](v3-migration-followups-20260920.md) records subsequent user decisions without changing this historical assessment.

Assessment date: 2026-09-20. Reviewed checkout: `f0320308c2ee055dde71bde80eee9268fad335de`, plugin 3.2.0. Historical implementation reference: `867c9f336b0a56ee4a992c93a54d21a2c5d92c1d`. This is an independent, read-only product assessment requested while the controller conducts triage. It is not a clean implementation review, delivery run, or publication gate.

## Outcome

The history contains twelve shipped pre-v3 entries and one proposal explicitly superseded without shipping. The current implementation retains the dependency parser, draft data, portable skill architecture, version policy and substantial replacement review safeguards. Removing the old wave scheduler, mandatory verifier, tier calculator, digest machinery and dedup judge was deliberate. Their disappearance is not itself a regression.

The deterministic setup feature lost more than the four previously listed restoration candidates. The most consequential confirmed loss is recoverable mechanical repair: current setup's optional unwrap path can destroy existing backlog text after a partial write failure, retain no recovery copy, and then accept the truncated file on a rerun. Interrupted creation of a missing template has a related, separate false-success recovery case. Private ignore-source preservation, project newline policy, current-scaffold inspection and legacy recovery diagnosis also need explicit accounting. Exploring lost its specific instructions to report every parser problem channel.

The earlier blanket non-Git description needs correction: fresh non-Git initialization does run successfully. It nevertheless writes Git ignore files, and non-Git legacy migration fails. A malformed Git marker is also not detected on the fresh path. These are different branches, not one absent implementation.

There were 231 passing deterministic cases in the selected checks and eleven ordinary setup probes, plus two interruption probes. Passing existing tests did not detect the confirmed regressions. No real model or native acceptance campaign ran. Existing native reports are qualified below and are not promoted into current-candidate blanket validation.

## Method and evidence custody

All source references below are repository-relative `file:line` locations in the reviewed current checkout, unless marked `historical`. Historical source was read through local Git, without networking or history changes. The historical feature records were used to enumerate purposes and material sub-capabilities, then challenged against implementation and tests. The provisional accounting and follow-up report supplied leads, not acceptance authority.

`run-checks.cjs` copied current tracked file bytes into this directory's `snapshot/` and recorded their SHA-256 values in `snapshot-manifest.json`. Tests ran against that byte-for-byte source snapshot so their repository-local fixtures stayed inside the audit directory. The final recorded run also redirected `TMP`, `TEMP` and `TMPDIR` into `test-temporary/`, since some retained tests use the platform temporary-directory API rather than project `.tmp`. The first exploratory execution used the tests' normal temporary directories; those fixtures have ordinary suite cleanup. No canonical product file, index, runtime record, Git index or branch was edited by the audit.

The deciding custom probes require the actual canonical modules, not reimplementations. `probes.cjs` confines fixtures below `probes/` and sets `GIT_CEILING_DIRECTORIES` to that parent so a non-Git fixture cannot accidentally discover the surrounding Nightshift checkout. The final records are `probe-results.json`, `unwrap-interruption-results.json` and `setup-unwrap-interruption-results.json`. Earlier fixture directories are preserved as diagnostic scratch; only the final JSON is the cited result.

Verdicts mean:

- **Present:** current code or instructions implement the named capability, with the stated evidence level. This does not imply every host or failure branch was exercised.
- **Partial:** a composite behavior survives only in part, or its required product instruction is weaker than the retained implementation purpose.
- **Missing:** no current implementation/instruction for the named behavior was found and the deciding path establishes its absence.
- **Intentionally replaced/removed:** a governing decision explicitly permits the changed behavior or mechanism. Its surviving purpose is assessed separately.
- **Unverified:** available evidence does not establish the result. Absence of a test is not a product failure, and a broad prior acceptance report is not a substitute for the specific case.
