# Physical plan binding

This resource defines the contract enforced by the bundled `plan-binding.js` service, the sole owner of plan-path classification, containment, link safety, repository Git policy, bounded candidate evidence, binding revalidation, mutation refresh, and deletion for every Nightshift workflow that treats an implementation plan as authority. A caller owns only its local selection judgment, mutation bytes, dispatch, and user-facing deletion approval.

## Bind candidate evidence before inferred selection

A plan path selected solely from an exact user or system supplied path, or from conversation context that needs no candidate filesystem metadata or content, may proceed directly to Establish the binding. Before modification time or content can influence inferred selection, pass a names-only enumerator to `capturePlanCandidateEvidence`; the service records the first candidate set, establishes a binding and performs the stable two-read capture for every candidate, then enumerates the names again and requires a stable candidate set: duplicate-free membership by exact ordinal `(logicalPath, exactUserPath)` identity while allowing enumeration order to differ. Returned evidence retains the first enumeration's order. A candidate that cannot be bound or captured stops selection with its path and the typed failure reason; silently excluding it could change the winner. The service accepts at most 128 candidates, at most 2,097,152 bytes per plan, and at most 16,777,216 retained candidate bytes in aggregate. It rejects a stat-reported oversize file before allocation and also reads through the retained handle only up to the byte limit plus one, so metadata drift cannot bypass the cap. Callers use the direct Buffer-returning exports and never hex-expand captured plan authority through the agreement CLI.

Trusted Git executable resolution is lazy and capture-local. The first repository-local candidate in a Git repository that reaches the default Git policy resolves one trusted executable, and later repository-local candidates in that same `capturePlanCandidateEvidence` call reuse it. A caller-supplied `gitExecutable` remains authoritative without resolution, while a custom `gitPolicy` continues to own its complete Git behavior. A capture containing only global, external, or confirmed non-Git candidates performs no executable resolution. The retained executable is discarded when the capture returns or fails; a later capture resolves independently and no cross-operation cache is persisted.

Perform recency comparison only from each binding's `mtimeNs`, and perform content matching only from that binding's captured bytes. Select from this frozen evidence. Once a candidate wins, retain that candidate's existing full binding, discard the other candidate bindings and bytes, and call `revalidatePlanBinding` before its first authoritative use. Never reopen the winning logical path merely to establish a second binding.

## Establish the binding

Before the first authoritative plan read, call `establishPlanBinding` to establish a stable physical plan binding that records the logical path, declared boundary, resolved physical path, repository and global roots, stable file identity, link count, file size, stable content metadata, plan classification, repository-relative path when applicable, and whether the user supplied the exact path. The stable content metadata is the file's nanosecond modification and change times. The full binding remains the lifecycle authority. `toProvenanceBinding` projects only the canonical provenance fields `ctimeNs`, `dev`, `ino`, `mode`, `mtimeNs`, `nlink`, `realPath`, and `size` in that order at the provenance writer boundary; every numeric value is a nonnegative decimal string, `nlink` is `1`, `mode` identifies an ordinary file, and `realPath` is the resolved physical path.

Resolve the physical repository root, the global `~/.claude/plans/` root, and the selected path before classifying it. Any selected plan physically inside the repository root is repository-local, regardless of whether it came from the standard `.claude/plans/` directory, a project-established custom location, inference, or an exact user-supplied path. Its declared boundary is the resolved physical repository root. Require every actual component from that root through the selected file to be an existing ordinary directory or file, reject a symbolic link, junction, or other reparse point, and prove the plan remains physically inside the repository root.

A selected plan outside the repository but physically inside the global plans root is global and uses that resolved root as its boundary with the same component and containment checks. An external plan is accepted only when the user supplied that exact path. It must be outside both prior roots and uses its existing physical parent directory as the declared boundary. For every plan type, reject a missing or non-regular file and require that the selected plan file's link count is available and exactly one, so a hard-linked leaf cannot authorize access through a peer path.

Before accepting a repository-local plan as authority, classify the repository root from its direct `.git` metadata. Absence is the only confirmed non-Git state. An ordinary `.git` file or directory classifies the root as Git; malformed ordinary metadata then fails through the closed Git command checks. Linked, special, or unreadable metadata is ambiguous and stops with `plan-git-policy`. For a Git root, verify that the plan's actual repository-relative path is ignored and untracked. The standard `.claude/plans/` directory is unconditionally ignored. A project-established custom location must carry an applicable ignore rule, and an explicit unignore, uncovered path, or tracked file stops the run for user remediation. A confirmed non-Git root skips only those Git ignore and tracking checks. Global and external plans are outside the current repository's ignore policy and receive no project Git check.

## Revalidate and consume

Retain the full binding for the complete plan lifecycle. Call `revalidatePlanBinding` immediately before every authoritative plan read, plan mutation, or plan-derived dispatch. It re-resolves the boundary and path, repeats the component, containment, kind, link, single-link, and size checks, requires the same file identity, reclassifies every repository root, and repeats the ignored-and-untracked Git policy check for a Git root. Establishment and every later revalidation also classify the root again after stable plan capture and fail if Git versus non-Git status changed across that operation. Call `deleteBoundPlan` only after user-facing deletion approval; it performs the same immediate revalidation, deletes only that binding, verifies absence, and invalidates the returned binding. A missing bound plan at that final optional-removal site returns `alreadyAbsent` and never selects a replacement.

For an authoritative read or plan-derived dispatch, successful revalidation returns the plan bytes read from the revalidated file identity. The caller consumes those captured plan bytes directly and never rereads the logical pathname between revalidation and use. Read through one no-follow file handle twice from the beginning. Before, between, and after the complete reads, require the handle identity, single-link state, size, and stable content metadata to match the binding and one another; require the captured bytes and stable content metadata agree across both reads; and require the resolved path to identify that same file after the reads. Any disagreement invalidates the capture and stops the operation rather than retrying against moving authority. A reviewer, skeptic, parser, task-brief helper, or implementation agent receives the captured bytes or content derived directly from them, never a pathname it is expected to reopen as authority.

For a mutation, use the captured bytes as the writer's exact baseline and keep the existing full binding until the write succeeds. Immediately before replacement, repeat `revalidatePlanBinding` and require that the destination still has the captured baseline bytes, identity, link state, size, and stable content metadata. Refuse the mutation on drift. A plan provenance mutation calls `writePlanProvenanceStamp`; the service checks the complete intended bytes against the plan cap before mutation, projects the reduced provenance binding only for `writeBoundProvenanceStamp`, then calls `refreshPlanBinding` over the writer's exact returned bytes and returns the refreshed full binding. After every other successful replacement, call `refreshPlanBinding` with the intended bytes; it repeats the complete establishment checks and preserves the immutable authority fields while replacing physical identity fields. A failed or ambiguous mutation invalidates the binding. This compare-before-replace contract detects drift up to the final replacement boundary; it does not claim preservation against an uncooperative writer in the replacement syscall itself. A successful `deleteBoundPlan` ends the plan lifecycle and returns a null binding without refresh.

Any revalidation or capture failure stops the run before any read, write, dispatch, or deletion and requires fresh selection. It never reads, edits, dispatches from, or removes the replacement target. A missing plan at a final optional-removal site is reported as already absent; it does not authorize selecting a different file.
