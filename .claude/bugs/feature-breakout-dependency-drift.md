# Feature breakout dependency lines drift from the active index

Bug: feature breakout files duplicate active `Requires:` state from `FEATURES.md`, but the shipped-dependency walk updates only the index and no validation detects the copies that become stale.

## Observed behavior

The universal-skill MVP shipped and its active dependency references were removed from `FEATURES.md` under the walk-and-remove convention. A repository sweep on 2026-08-18 found eight breakout files still claiming that the shipped MVP was required:

- `sophisticated-user-communication.md`
- `review-orchestration-tests.md`
- `deterministic-init-backlog.md`
- `present-spec-for-agreement.md`
- `fix-scoped-rounds.md`
- `durable-scope-anchor.md`
- `durable-run-identity-concurrency.md`
- `adversarial-repair-dialogue.md`

The arbitration design change corrected the copies in the four breakout files it otherwise touched: `review-orchestration-tests.md`, `fix-scoped-rounds.md`, `durable-scope-anchor.md`, and `adversarial-repair-dialogue.md`. The agreement-gate release later corrected `present-spec-for-agreement.md`. The other three remain concrete open instances.

`skills/ready/ready.js` correctly treats the top-level `**Requires:**` lines in `FEATURES.md` and `BUGS.md` as the active dependency authority. It does not read breakout-file copies, so `/nightshift:ready` reports a healthy graph while a human or agent reading the authoritative design record sees stale ordering. The `(FEATURES.md index entry)` suffix makes those lines look intentionally synchronized even when they are not.

## Impact

- An implementation session can wait on already shipped work or describe the wrong landing order.
- A review can "fix" the correct index excerpt back toward stale breakout prose.
- Search results expose contradictory dependency state without identifying which copy is authoritative.
- The walk-and-remove convention appears complete while leaving durable design records inconsistent.

## Operating context

Nightshift is a locally installed, personal-use coding-agent plugin; `ready.js` runs as a read-only parser on demand, never as a service. The audience is one expert developer: the repository is public on GitHub but has no adoption signals, so the category is `personal use` per the 2026-08-15 calibration ruling.

A defect here misreports the work set or raises a spurious structural error in a backlog index; no data, credentials, or outward state are touched, and the wrong report is visible on the next `/nightshift:ready` run. The change is host-neutral Node with no concurrent use. Recovery is a git revert plus a plugin release, so reversibility is cheap. The index grammar is long-lived: every backlog consumer (`ready`, `exploring`, `spec-agreement`, `init-backlog` templates) reads it and the two-line convention is expected to outlast this fix.

Rigor derivation: `personal use` gives a low baseline. The expected-lifetime predicate fires because the grammar is foundation for every backlog consumer; criticality, failure-consequence, compatibility, and reversibility predicates do not. One uplift yields a `medium` tier: validation, recovery, compatibility, observability, and proof effort are all medium.

## Expected behavior

The index is the sole authority for queue state. Breakout files carry no active dependency line; their `## Requirements` sections hold only standing architectural prerequisites, never queue status. Keeping the copies as a deliberate convention and extending the shipped-item walk with a synchronizer was considered and rejected: a synchronizer has to be maintained and can itself drift, while a breakout with no line has nothing to go stale.

The root cause of the undecidable "architectural capability versus queue status" boundary is that one `**Requires:**` field holds two things with opposite lifecycles: in-backlog links, which the walk-and-remove convention deletes the moment their upstream ships, and external primitives, which are standing properties of the design and are never walked. The fix splits the field:

1. `**Requires:**` holds only in-backlog markdown links or the literal `none.`. Bare text in it becomes a structural error, and so does a label with no items: `none.` is the only empty form. The rule applies to the top-level entry line and to every indented per-slice inline `**Requires:**` annotation alike, because `ready.js` feeds both through one grammar. Cycle detection consumes that grammar too: bare text on a top-level line is a structural problem that masks the entry's whole edge set, exactly as a missing line or a structurally broken link does today, and every existing `ready.test.js` fixture carrying bare text in `**Requires:**` (one pure bare-text fixture asserting External, and three that mix a link with bare text: the cycle fixture, a top-level wrapped line, and an indented per-slice annotation) moves its bare text to `**External:**`.
2. A new `**External:**` line holds bare-text external primitives (SDK features, infrastructure, hardware). Its grammar mirrors `**Requires:**`: comma-separated items, the same wrap-join rule, and a terminating period. It is optional, patterned after the optional `**Slices:**` block rather than the mandatory `**Requires:**` line: the dependency-review-done signal that makes `**Requires:** none.` mandatory is still carried by `**Requires:**` alone, so an absent `**External:**` line is not suspect silence. Absence is the only empty form, so a literal `none.`, a label with no items, or a markdown link in it is a structural error (a link parked there would be invisible to the walk-and-remove convention). A link means an item that is entirely a markdown link, by the same whole-item test the Requires grammar uses; prose that merely contains a link is bare text. The top-level line governs the entry's first unshipped work unit; a later slice declares its own indented `**External:**` annotation beside its inline `**Requires:**`, exactly as inline `**Requires:**` works today. The slice-shipping protocol therefore advances both top-level lines to the next-to-ship slice's gates, dropping the top-level `**External:**` line when that slice declares none. The archive move drops both lines, exactly as it drops `**Requires:**` today; history entries carry neither. `/nightshift:ready` feeds its External classification from these lines only. Precedence is unchanged: a work unit with at least one in-backlog blocker (a `**Requires:**` link or the implicit MVP gate a continuation slice inherits) classifies as Blocked with any externals noted parenthetically, and only a work unit with externals and no such blocker classifies as External.
3. Breakout files under `.claude/features/` and `.claude/bugs/` carry neither line, exploring drafts and history-linked files included. The one-time cleanup removes the three stale universal-MVP copies along with every other breakout `**Requires:**` line, `none.` forms included, and refreshes the hardening stamp of every stripped file that carries real provenance (a deleted design line moves the fingerprint, which the agreement test gate checks); a placeholder `## Hardening` body carries no fingerprint and is left alone.

The rule covers features and bugs, and excludes plans, history archives, and pattern files: `PATTERNS.md` is a registry `ready.js` never parses, a pattern is not a work item, and a pattern file carrying either line is a convention violation for review to catch, not a parser case. Detection is link-scoped: `ready.js` scans each breakout file linked from an active index entry for either line and reports a structural error naming both the index entry and the breakout path. The link set is every breakout link in the two active work indexes, including entries whose own classification terminated in a structural error (today `breakoutTargets` drops those for sliced entries). A breakout carries a line when a line outside any code fence, at any indentation, has trimmed content starting with `**Requires:**` or `**External:**`; inline backticked mentions in prose never match. A linked target that exists but cannot be read as a file (a directory, an anchor-only link) is skipped with a notice naming both paths, beside the existing missing-file notice; the scan never aborts the report. A breakout reachable only from a history archive is cleaned once and never edited again, so it cannot regress. The scan reads breakout bodies, which `analyze()` cannot do because it is pure over the three index strings; the scan therefore lives beside the existing missing-breakout check in `runCli`, as an exported function over in-memory breakout contents so `ready.test.js` fixtures can drive it. Unlike every entry-level structural error, which replaces the entry's classification, a breakout-line error is a hygiene error: the entry's `ready`, `blocked`, or `external` classification stands, because the index still describes the queue correctly. `skills/ready/SKILL.md` documents that exception in its structural-error taxonomy.

Every new structural error carries a remedy in its message: bare text in `**Requires:**` names the offending item and says to move it to `**External:**`, writing `none.` if no link remains; an empty `**Requires:**` label says to write `none.`; a link in `**External:**` names it and says to move it to `**Requires:**`; `none.` or an empty label in `**External:**` says to delete the line; a breakout line names both paths and says to delete the breakout line. That message is the upgrade path for backlogs scaffolded by earlier plugin versions, where bare text was documented as legal: the first `/nightshift:ready` after the upgrade lists every offending line with its remedy. No migration tool ships. An idempotent `init-backlog` re-run refreshes template prose only, never entry data, and because its patch machinery is append-only it gains one replace rule, beside the existing automatic-loading one: an index header whose `## Requires lines` section still describes bare text as a legal `**Requires:**` form has that whole template-controlled section replaced by the current template's section through the existing user-confirmed section-level merge route, since the legacy section states the form in its bullet list and, in `FEATURES.md`, also in its form count and fenced example. Within this repository's backlog data the bare-text branch has zero live users, so no index entry needs moving; its only users are the test fixtures named above.

Landing order: this fix lands before the two `ready.js` quick wins in `QUICK_WINS.md` (reusing parsed ready-entry metadata, and splitting the scanner out of the agreement controller), before `Content fingerprint helper` extracts the shared raw-entry locator from `ready.js`, and before `deterministic-init-backlog` relocates the `init-backlog` templates, so each of those reshapes the grammar and templates this fix has already changed rather than the other way round. The implementation records that order in each of those four entries. The `revise-docs` prose edit lands through the procedure-fidelity whitelist (`PROCEDURE_REPLACEMENTS` in `tests/entry-contract.js`, empty for `revise-docs` today) as a phrase pair, the mechanism that whitelist exists for; the quick win that retires the 2.4.5 baseline and its pin lands after this fix and removes the pair with the pin.

## Acceptance criteria

- No breakout file under `.claude/features/` or `.claude/bugs/` carries a `**Requires:**` or `**External:**` line; the three stale universal-MVP copies are gone with the rest.
- `ready.js` rejects bare text in top-level and inline `**Requires:**` as a structural error, accepts `**External:**` at both levels with the Requires grammar, rejects `none.` and links in it, classifies External from `**External:**` only, and reports a hygiene structural error naming both paths when a linked breakout carries either line while leaving that entry's classification intact. Every new error message states its remedy.
- Fixtures in `ready.test.js` cover each new structural error (asserting its remedy clause, not only that it fires), the coexistence of a breakout-line error with the entry's classification, a breakout linked from an entry whose own classification terminated in a structural error, an inline per-slice `**External:**` annotation, a wrapped `**External:**` line, an entry with a `**Requires:**` link and an `**External:**` line (Blocked, externals parenthetical, absent from External), an `**External:**` item whose prose contains a link (External, no error), a breakout whose only `**Requires:**` mention is inline backticked prose (no error), a breakout whose only occurrence sits inside a fenced block (no error), a breakout whose line is indented (error), a CLI run whose linked target is a directory (notice, report still emitted), a breakout linked from an `## Exploring` draft entry that carries a line (error), an empty-label `**Requires:**` line and an empty-label `**External:**` line (each an error), a mutual-reference pair whose top-level lines carry bare text (the bare-text error fires and no cycle error is emitted, because the edge set is masked), a later unshipped slice whose indented `**Requires:**` carries bare text (the bare-text error with its remedy), and confirm that `## Requirements` prose, inline per-slice `**Requires:**` annotations holding links, history archives, and plans trigger no error.
- `AGENTS.md`, the `FEATURES.md`, `BUGS.md`, and `QUICK_WINS.md` headers (including, in `FEATURES.md`, the fenced example and the slice-shipping protocol), `README.md`, the `ready` skill prose (its structural-error taxonomy, its External description, its read-set sentence, and the sentence claiming the script never crawls breakouts), the `exploring` skill prose (including its never-crawl note that cross-references the ready skill), the slice-shipping and archive-move steps in the `revise-docs` and `handover` skill prose, and the `init-backlog` templates, concept checklists, and the new bare-text replace rule describe the two-line convention consistently. The legacy fixture tree under `tests/fixtures/` is frozen and excluded.
- `skills/spec-agreement/spec-agreement.test.js` no longer pins `**Requires:**` lines inside breakout `## Requirements` sections: the `designRequirement` assertion is dropped for the pairs whose only pinned line was a `**Requires:**` line, while the index-excerpt and ordering-sentence assertions stay.
- The four entries named under Landing order carry the recorded order, the 2.4.5 pin-retirement quick win gains a one-clause pointer to the `revise-docs` phrase pair it removes, and the `revise-docs` edit is whitelisted as a `PROCEDURE_REPLACEMENTS` phrase pair; the `QUICK_WINS.md` constraint "Preserve the exact Requires-line grammar" is reworded to name the post-split grammar.
- The shipped-item walk cannot leave an undetected stale breakout `**Requires:**` or `**External:**` line behind, because a breakout has no such line to go stale. Prose in a breakout body that mentions another entry is design narrative, not queue state, and stays outside detection by design.
