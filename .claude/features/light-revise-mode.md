# Light revise mode

Codify a lightened shape of the revise review workflows for interactive sessions: one fresh reviewer per iteration instead of the full per-dimension swarm, and a curated dimension set that skips the dimensions least relevant to the artifact under review.

Prompted by the 2026-08-11 revise-spec run over `.claude/features/dependency-cycle-detection.md`, where the swarm was deliberately collapsed to a single reviewer carrying five of seven dimensions (D3 scope/decomposition and D6 reasoning-preservation skipped as least relevant for a small, non-sliced parser feature).

Observed evidence from the same 2026-08-11 handover: the lightened shape ran well in practice for BOTH artifact types. The spec review (D1/D2/D4/D5/D7, one fresh opus reviewer per iteration, fresh-skeptic verification of every finding) converged over four phases and caught two genuine false-deadlock design vectors plus a code-fidelity wording error; the plan review (D1 plan-correctness + D7 commit hygiene, cut to the two durability-relevant dimensions) caught one instruction-precision defect over two phases. Conclusion: a single fresh reviewer carrying a curated dimension set is a viable interactive proxy for the full swarm when cost constraints apply, and the dimension-curation choice is the mechanism that keeps it lossless. The mapping of reviewer convergence->SCC-not-truth held unchanged.

Further evidence from the 2026-08-22 handover over the two `## Ready parser precision` quick wins (index-only entries, no breakout file), run at the user's direction with one fresh opus reviewer per round carrying the full dimension set (no curation) and no skeptic layer, findings verified by the controller reading the parser directly instead. Spec gate: five rounds, four of them each landing one verified important finding (cycle-member and sliced-entry outcome coverage, cross-entry precedence, missing-Requires ordering, and a continuation-slice Requires the cycle error never owns) before an anchoring-only fifth round; one finding widened the accepted contract and correctly forced renewed agreement through the post-mutation gate. Plan review: two rounds, with the reviewer executing the plan's embedded edits in a scratch copy, catching a vacuous `tail -3` verification gate. Code review: LGTM with a concrete verification note plus two scout-rule minors. Observations: convergence took five spec rounds for two paragraphs of design, so single-reviewer depth substitutes for swarm breadth but not for round count; the later rounds' yield came from the reviewer tracing reachability and executing embedded code, not from dimension breadth; and dropping the skeptic layer answers the open question about skeptic verification only partially, since it held up here because the controller could verify each finding by reading the parser directly, a substitute a larger or less legible artifact would not offer.

Reflections from the 2026-08-22 run, for the graduation design. First, the light shape was improvised against the engine rather than inside it: no state file, no checkpoints, and the hardening stamp was written by hand through `writeProvenanceStamp` after the loop. A codified light mode must keep the stamp and the fingerprint certification, because handover stage detection reads nothing else; light is a scheduling change (one cell per round, the round being the unit of certification), not a completion-contract change. Second, the convergence rule used was "a round with no critical or important finding ends the loop, minors apply under the scout rule without another round"; that leaves the minor fixes uncertified over the final fingerprint, which the engine's verifier stamp would not allow, and applying then not reviewing is a standing source of errors. Ruling (2026-08-22): light mode does not apply minor findings at all. A round that returns only minors is clean by construction, the stamp covers exactly the reviewed bytes, and the minors route to the follow-up list for the user to rule on with full context; a minor the user wants fixed re-enters as ordinary work with its own review. Third, what made a single reviewer carry all dimensions was scaffolding the engine already has: the pre-seeded acknowledgements list grown per round (no re-flags across five rounds), the "expect subtler residue; a clean verdict is legitimate" calibration, and the mandate to execute embedded code instead of reading it. Light mode should reuse the parameter files verbatim and vary only the dispatch. Cost calibration: each reviewer round ran 100k to 125k subagent tokens and four to six minutes; the artifact was two paragraphs, so the per-round cost is dominated by the reviewer reading the code under review, not the artifact. Where the controller cannot verify findings by reading the target directly, the cheapest honest middle shape is one reviewer plus one skeptic per round rather than the full per-finding skeptic fan-out.

Open questions to settle when it graduates to a designed feature: how the dimension-curation rule is chosen (artifact-type defaults vs per-run judgment), how the wave-convergence-plus-verifier-stamp completion conjunction maps onto single-reviewer iterations (iterations map onto rounds and certifications; the mandatory opus verifier launch is a per-run cost floor a light run must absorb or explicitly re-dispose, and the empty-applicable-set failure bounds how far dimension curation can shrink the set), whether skeptic verification of every finding still holds at lower cost, and whether it rides the existing revise syntax (e.g. a `--light` flag) or is a separate entry point.
