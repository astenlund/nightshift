# Wave-convergence lifecycle with a holistic gate

Feature: the revise review engine's phase model is removed. A run converges through rounds and reactivation waves until every applicable dimension cell has certified the current artifact fingerprint, then a fresh holistic verifier reviews the whole artifact at that fingerprint. The run completes only on the conjunction of wave convergence and a verifier stamp over the same fingerprint. A clean LGTM with a concrete note earns that stamp; only a current verifier round that applies no fix and creates an authoritative deferred follow-up may stamp without one. This file is the authoritative design record. It supersedes the retired "Simplify the revise lifecycle around rounds" feature (`revise-lifecycle-rounds.md`), whose motivating observations and still-valid ingredients are absorbed below.

## What it does

Today the lifecycle runs phases: each phase reviews per dimension until every dimension is inactive, and completion requires at least two converged phases, the last of which must be change-free. Phase convergence is weak (dimensions certify different fingerprints within one phase), the terminal phase re-runs all dimensions against a fingerprint the last-settling dimensions just certified, and the phase vocabulary itself has caused real controller failures: two observed phase-1 short-circuits on 2026-08-12 where a "dirty" phase was misread as the trigger to start phase 2, both requiring human interruption.

This feature replaces phases with a single convergence process:

- Rounds launch one fresh reviewer per active cell. Only a clean LGTM with a concrete note certifies the reviewed fingerprint. A finding-bearing round keeps its cell active under every disposition: an applied fix, an open follow-up, or a round in which every skeptic-verified finding was refuted or accepted as an acknowledgement-only judgment call. Reasoned acknowledgements from the latter route persist into the next payload so a fresh reviewer can cover ground beyond the rejected claim.
- When every applicable cell is inactive, cells whose certified fingerprint differs from the current fingerprint are reactivated (a reactivation wave) and rounds continue. Wave convergence is reached when every applicable cell's certification equals the current fingerprint.
- At wave convergence, one fresh holistic verifier reviews the entire artifact at that fingerprint, and its findings enter the normal skeptic pipeline in every branch. A clean LGTM with a concrete note stamps the reviewed fingerprint and enters post-review. A verifier round in which every skeptic-verified finding was refuted or accepted as an acknowledgement-only judgment call leaves the stamp unset; its reasoned acknowledgements enter the next payload and another fresh verifier reviews the same fingerprint. Only a current verifier round that applies no fix and creates an authoritative deferred follow-up may stamp without a clean LGTM. This exception is a deliberate departure from the cell rule: relaunching the verifier at the same fingerprint cannot resolve accepted debt, and the stamp attests review coverage of the artifact, not zero deferred debt. Confirmed verifier fixes are applied at a verifier boundary with round-boundary semantics, staleness reactivates every cell whose certification no longer equals the new fingerprint, and the loop re-converges before the verifier runs again.

## Settled design decisions

- **The staleness sweep is the named boundary action at every all-inactive point**: compare each applicable cell's certification with the current fingerprint, reactivate every unequal cell, and re-evaluate N/A applicability in both directions. Wave convergence has exactly one definition, the extensional one: every applicable cell's certification equals the current fingerprint. A sweep blocks convergence only by activating a cell (reactivating a stale one or promoting a contradicted N/A); a demotion-only sweep shrinks the applicable set and converges immediately, with no further review owed. A sweep that finds the applicable set empty fails the run closed with a structural error: wave convergence is never vacuous, and the verifier can never be the artifact's only fresh look. Staleness is evaluated only at this sweep, never mid-round, and is computed as inequality: a cell is stale exactly when its certified fingerprint differs from the current fingerprint. Digests carry no order, and a certification can only name an earlier artifact state, so inequality is the whole test. This batches accumulated changes into one wave instead of re-running settled cells per tiny delta. (Simulation controllers flagged the absence of this rationale; it is now explicit.)
- **A certification requires an affirmative clean LGTM**: refuted-only and acknowledgement-only rounds establish that the reported finding does not justify an edit, not that the reviewer covered the rest of its scope. The reasoned acknowledgement persists into the next payload to suppress repetition, and the 30-round cap fails closed if fresh reviewers never produce a clean pass. The holistic verifier follows the same rule. Only a current verifier round that applies no fix and creates an authoritative deferred follow-up may stamp without a clean LGTM, because another pass cannot resolve debt the workflow has intentionally accepted.
- **Reactivation clears the cell's certification**; the cell holds none until it next deactivates through a certification route.
- **N/A applicability is re-evaluated at every staleness sweep, in both directions.** A newly contradicted N/A declaration becomes active immediately with no certification, so the run cannot converge or stamp without reviewing it; an inapplicable cell stays N/A only with a re-evaluated nonblank reason. Demotion is equally defined: a cell whose applicability re-evaluation (at a sweep, or at a remap re-evaluation) shows it no longer applies becomes N/A with a newly evaluated reason, clearing its certification; demotion happens only at those boundaries, never while the cell's round is in flight, and any open follow-ups it produced remain in the run-wide follow-up ledger, which is not cell-scoped. Completion deliberately quantifies over the applicable set: a correctly demoted cell leaving the conjunction is intended behavior.
- **Remapped shard cells carry certifications deterministically.** An unchanged logical cell keeps its identity, status, and certification across label changes; a change to its slice membership clears the certification and reactivates it, because the certification attests exactly the slice that was reviewed and slice content can change without the artifact fingerprint moving. The same principle governs whole-scope and cross-cutting cells: a change to the resolved scope map clears their certifications too, because delivered content changed even when the patch fingerprint did not (for code, the fingerprint covers only the cumulative patch, so fingerprint inequality alone cannot detect scope expansion). A split or merge mints a new cell recording ordinal predecessor IDs. A split child whose slice is a subset of a single inactive predecessor's certified slice inherits that predecessor's certification (the certified review covered a superset of the child's content; this is the one deliberate exception to membership-change clearing). Every other minted cell, including every merge (whose union slice no single reviewer ever certified as a unit), every child of an active predecessor, and every cell with no applicable predecessors, starts active with no certification.
- **The verifier boundary is a round boundary in all but name**: apply every confirmed fix once, increment the fingerprint once if at least one fix applied, trigger spawned consequences, record applied changes. (Simulation controllers flagged that fingerprint increments were defined only for round boundaries.)
- **The stamp is a conjunction, not an authority.** The verifier can only decline to block: it never runs before wave convergence, its stamp names the exact fingerprint it certified, and post-review entry requires the stamp to equal the current fingerprint at a wave-converged state. No single agent can complete the run alone, preserving the engine's no-manufactured-LGTM invariant. Any later reviewable-content edit moves the fingerprint, and any resolved-scope-map change alters delivered content even when the fingerprint holds; either event invalidates the stamp and clears or stales the affected certifications, and the staleness machinery is the single re-entry path in both cases.
- **Acknowledgements, follow-ups, applied changes, and refuted-finding acknowledgements persist for the whole run** (they already do; stated here because the phase-reset rule that previously created ambiguity about their scope is gone).
- **Identity simplification**: with no phase resets, the round number is monotonic per run, so run identity tuples become (round, fingerprint, delivery snapshot). The workflow invocation contract drops its `phase` field.
- **Pre-wave state is not migrated** (explicit anti-goal): a resume that encounters an in-flight `.tmp/revise-state.md` written by the phase-model version fails closed with diagnostics and offers restart or abandon; no schema migration and no state-file version marker are added. Scratch state is temporary by design and a restarted run loses only round progress, never the artifact.
- **Caps**: at most 30 rounds per run (verifier rounds count against this cap too) and 10 verifier launches per run, both preflight-checked and fail-closed with diagnostics; the per-cell execution-repair budget of 3 is unchanged, and repair launches never consume a round. The per-cell 10-attempts-per-phase counter is removed (the run round cap bounds total work). No cap path can manufacture LGTM, a stamp, or refutation.
- **Verifier parameters**: stable cell ID `verifier/whole-artifact`, fresh agent per launch, pinned to opus for every artifact type (a single seat carrying completion weight warrants the stronger tier; the code profile's volume rationale for sonnet does not apply to one agent). The verifier reads the whole artifact plus the standard common context and a holistic charter: cross-dimension coherence, gaps between dimension lenses, and completion-worthiness, reporting high-confidence findings only, with a concrete verification note required for a clean conclusion.

## Why completion stays sound

Completion previously attested: every dimension certified the final artifact in a terminal change-free phase, after at least two phase convergences. Under this design it attests: every dimension returned a clean LGTM against the exact final fingerprint, stronger than phase convergence's mixed fingerprints, and an independent fresh holistic agent reviewed that same fingerprint. The verifier either returned its own clean LGTM or created an authoritative deferred follow-up in a current no-fix round. Every artifact state that reaches post-review has therefore received at least two independent fresh looks, including the pristine round-1-clean case that previously forced a full second phase. The trade accepted: the second look thins from a full per-dimension pass to one holistic seat; in exchange it gains a lens no dimension has (cross-dimension coherence), and the wave model means most cells have already re-reviewed the artifact across waves with fresh eyes each time.

The retired all-refuted certification route established only that a reported finding did not justify an edit. It did not establish that a reviewer who latched onto that weak finding scrutinized the rest of its scope. Requiring another fresh pass buys affirmative coverage rather than repetition because the rejected claim's reasoned acknowledgement enters the next payload. The 30-round and 10-verifier-launch caps remain fail-closed livelock backstops.

## Simulation evidence (2026-08-13)

Ten opus controllers executed distilled instruction sets for the original wave design (B) against an enhanced-phase variant (A: phases forced to converge on the latest fingerprint, terminal full phase retained) over five deterministic scenarios with 0 to 32 fixes, including cascade damage, a second-look issue, a verifier-only issue, and refuted noise. All ten executions matched the hand-computed ground truth. This simulation predates the 2.4.4 clean-LGTM rule and models the retired all-refuted certification route, so its counts remain historical evidence for the wave architecture rather than current cost bounds. The current rule adds a fresh pass after any refuted-only or acknowledgement-only round. Original reviewer-run totals (A vs B, verifier counted separately):

| Scenario (fixes) | A | B |
|---|---|---|
| pristine (0) | 16 | 8 + 1 verifier |
| light (3) | 24 | 16 + 1 |
| moderate (11) | 37 | 29 + 1 |
| heavy (20) | 40 | 40 + 2 |
| churn (32) | 48 | 40 + 1 |

B saved roughly one full 8-dimension pass at every fix volume except the heavy scenario, where it spent the savings catching a cross-cutting verifier-only defect that A completed without ever detecting. Wall-clock steps tied everywhere except that same scenario (A finished faster by shipping the defect). The phase variant's controllers also independently flagged a completion-count off-by-one hazard (whether the converged-phase count includes the just-converged phase), the same hazard family as the observed 2026-08-12 production failures; the wave variant's ambiguities were definitional gaps now settled above. The simulation modeled the code profile's eight dimensions; plan and spec runs have seven, and every comparison scales the same way.

## Rejected alternatives

- **Enhanced phases (waves inside phases, phases retained)**: beaten in simulation at every fix volume except the heavy 20-fix scenario, where it finished cheaper and faster only by completing without detecting the cross-cutting defect; it never catches more, and the intra-phase wave duplicates the next phase's work because the full next phase still runs.
- **Ending at wave convergence with no verifier**: strictly cheapest, but the pristine case would complete on a single round of eight LGTMs, exactly what the old "Phase 1 cannot complete" rule exists to prevent; the verifier is the floor that preserves a second independent look in every run.
- **Restating the phase model more crisply** (the retired `revise-lifecycle-rounds` feature): a restatement reduces the mis-execution surface; removal eliminates it. Its round cap, cap-end asymmetry rule (a cap-forced end can never produce completion), and change-free-final-state rationale carry forward into this design. Its all-refuted deactivation trade was retired by the 2.4.4 clean-LGTM correction.

## Interactions

- **Fix-scoped follow-up rounds** (`fix-scoped-rounds.md`): composes only under a hard constraint this lifecycle imposes: a narrowed-payload review can never certify a fingerprint, because it reviews at the post-fix fingerprint while seeing only the fixes, and an LGTM there would otherwise mark the cell current off a partial look that the wave would never re-run. Certification requires a full-payload review; narrowed rounds validate fixes and keep the cell active. With that constraint, the reactivation wave replaces "the next phase's whole-scope reset" as that feature's full-coverage backstop. This lifecycle has shipped, so the active feature correctly declares no unresolved dependency on it; both its file and its FEATURES.md index excerpt record the wave-era constraint.

## Operating context

- **Deployment environment and operational criticality**: public GitHub plugin (`github.com/astenlund/nightshift`, self-hosted marketplace with autoUpdate); primary consumer is the author's daily workflow on Claude Code and Codex. The revise engine is the core of every downstream review loop; no production systems or external data are touched.
- **Audience**: published publicly with install instructions targeting arbitrary users. Judgment recorded: category `public` (the repository, marketplace, and README all address external installers, even though the author is the primary consumer today).
- **Failure consequence and data or security sensitivity**: a silently wrong lifecycle ships defective reviews into consuming projects and wastes large token budgets; no data or security sensitivity.
- **Concurrency and compatibility risk**: one active run per repository by design (no lock; the durable-run-identity feature tracks reversing that separately); dual-host compatibility (Claude Code and Codex) and dual dispatch paths (Workflow and manual Agent) must stay in parity.
- **Reversibility and recovery cost**: high reversibility; git-tracked prose with version-pinned releases, and consumers can pin or downgrade.
- **Expected feature lifetime**: long-lived; this is the engine's core lifecycle, not an experiment.

## Verification

- The motivating claim that removing phase vocabulary reduces controller lifecycle mis-execution is owned by the LLM controller runtime; the deterministic simulation cannot settle it. Probe: run one real wave-model review of each artifact type (code, plan, and spec) and record every controller lifecycle deviation that requires human interruption, the 2026-08-12 failure signature. Pass condition: zero such interruptions across the three runs; any interruption routes to prose correction or redesign (live-claim: provisional).
- The completion-soundness trade prices in the verifier producing genuine cross-dimension findings, a runtime-owned LLM behavior the simulation stipulated rather than demonstrated. Probe: across the first five stamped wave-model runs, covering at least one run of each artifact type (code, plan, and spec), record each verifier round's confirmed findings and whether any was outside every dimension's lens. Pass condition: at least one verifier-originated confirmed finding, or an explicit user re-evaluation of the thinned-second-look trade with the recorded counts in hand (live-claim: provisional).
